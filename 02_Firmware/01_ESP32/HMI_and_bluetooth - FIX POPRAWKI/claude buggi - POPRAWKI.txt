- `E i2c.slave: i2c_slave_transmit(350): no space in ringbuffer` — co dokładnie 5500ms
- `Queue feeding error` — 8-12 razy między każdym w/w błędem

## Zidentyfikowane błędy (NIE naprawione, do powrotu)

### Bug 1 — KRYTYCZNY: heap corruption w esp32PrepareKbrdDataAndSent_to_QueueSend()
**Plik**: `main/tasksFunctions/tasksFunctions.cpp` linia 273
```cpp
// BŁĄD — alokuje sizeof(size_t)=4 bajty, ale kopiuje itemSize bajtów
dataToTransmitQueue.pData = new char[sizeof(itemSize)];
// POWINNO BYĆ:
dataToTransmitQueue.pData = new char[itemSize];
```

### Bug 2 — KRYTYCZNY: vTaskSuspend() wywoływane z kontekstu ISR
**Plik**: `main/keyboard/keyboard.cpp` linia 422
```cpp
vTaskSuspend(handlerTask_keyboardLongPressOnPressQueueFeeder);  // w timer ISR callback!
```
`vTaskSuspend()` NIE jest API bezpiecznym dla ISR w FreeRTOS. To najprawdopodobniej powoduje, że task `keyboardLongPressOnPressQueueFeeder` nigdy nie jest prawidłowo zawieszany, przez co wysyła eventy `HMI_INPUT_BUTTON_LONG_AND_PRESSED` co 750ms mimo braku naciśnięcia klawiszy.
**Naprawa**: użyć `vTaskSuspendFromISR` jeśli istnieje, lub ustawić flagę i zawiesić z taska, albo użyć `xTaskNotifyFromISR` do komunikacji.

### Bug 3 — Przepełnienie I2C ring buffer (pierwotna przyczyna pętli błędów)
**Plik**: `main/i2c_engine/i2c_engine_slave.h` linia 42
```cpp
const int tx_timeout_ms = 5500;
```
Ring buffer sterownika I2C: `send_buf_depth = 2 × ESP32_SLAVE_RECEIVE_BUFFER_LEN = 2 × 52 = 104 bajty`.
Gdy STM32 (I2C master) jest wyłączony, `i2c_slave_transmit()` zapełnia ring buffer i każde kolejne wywołanie blokuje task na dokładnie 5500ms → stąd cykl co 5500ms.
Tymczasowe obejście: zmniejszyć `tx_timeout_ms` do np. 100ms.

### Bug 4 — Oba taski I2C mają ten sam uchwyt
**Plik**: `main/app_main.cpp` linie 94-95
```cpp
configASSERT(xTaskCreate(i2cSlaveReceive, ..., &handlerTask_i2cSlaveReceive));
configASSERT(xTaskCreate(i2cSlaveTransmit, ..., &handlerTask_i2cSlaveReceive)); // nadpisuje!
```
Uchwyt taska `i2cSlaveReceive` jest utracony (nadpisany przez `i2cSlaveTransmit`).

## Why / How to apply
**Why:** I2C master (STM32) jest wyłączony podczas testów / startu. vTaskSuspend z ISR jest niezdefiniowanym zachowaniem w FreeRTOS.
**How to apply:** Przy powrocie do tematu: zacząć od Bug 2 (vTaskSuspend z ISR) jako głównej przyczyny ciągłych eventów, potem Bug 1 (heap corruption), potem Bug 3 (tx_timeout_ms), na końcu Bug 4 (duplikat uchwytu).
